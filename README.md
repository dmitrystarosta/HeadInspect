# HeadInspect

HeadInspect — бесплатный массовый технический аудит сайта. Пользователь вводит адрес один раз, сервис находит sitemap и проверяет до 500 страниц без регистрации.

**Сайт:** https://headinspect.ru/

## Что работает

### Общий аудит

Главная страница запускает один обход сайта и использует его результаты для всех подключённых модулей. Готовый аудит получает `job`, поэтому между общим отчётом и специализированными страницами можно переключаться без повторного сканирования.

### Open Graph

Рабочая site-wide проверка:

- `og:title`, `og:description`, `og:url`, `og:type`, `og:image`;
- доступность и HTTP-ответ изображения;
- MIME и фактический формат;
- размер файла и реальные размеры изображения;
- несколько `og:image`;
- предупреждения и ошибки по всем страницам;
- Excel-отчёт.

Страница: `/open-graph/`.

### Meta

Рабочая site-wide проверка:

- `<title>` и его длина;
- `meta description` и её длина;
- `meta keywords`;
- `meta robots`;
- `viewport`;
- `lang`;
- `charset`;
- несколько одинаковых meta-тегов на странице;
- дубли title, description и keywords между URL;
- ошибки и рекомендации по всем страницам.

Для `meta keywords` HeadInspect учитывает российский контекст: Яндекс по-прежнему описывает тег как возможный сигнал соответствия запросам, а Google не использует его для ранжирования.

Страница: `/meta/`.

## Следующие модули

В интерфейсе уже зарезервированы отдельные страницы:

- `/canonical/`;
- `/schema/`;
- `/images/`;
- `/sitemap/`.

До запуска они остаются `noindex` и закрыты в `robots.txt`.

## Как устроен аудит

1. Нормализуется URL.
2. Проверяется доступность сайта.
3. Читается `robots.txt`.
4. Ищется sitemap / sitemap-index.
5. Собираются URL, максимум 500 страниц.
6. Страницы обходятся один раз.
7. Подключённые анализаторы используют результаты одного обхода.
8. Пользователь получает общий отчёт и может открывать специализированные результаты с тем же `job`.

## Аналитика и приватность

На всех страницах подключён единый механизм согласия на аналитику. Счётчик Яндекс Метрики `111906427` загружается только после согласия посетителя; выбор сохраняется локально для домена. Политика обработки персональных данных опубликована на `/privacy/`.

Единый футер подключён ко всем страницам, включая страницы будущих модулей и 404.

## Архитектура

```text
site/                 статический frontend (GitHub Pages)
backend/              FastAPI backend
backend/app/analyzers/ анализаторы модулей
docs/                 handoff и техническая документация
```

Frontend публикуется через GitHub Pages на `headinspect.ru`.

Backend работает отдельно на VPS и доступен через `api.headinspect.ru`. Контейнер запускается Docker Compose; внешний reverse proxy передаёт запросы приложению на `127.0.0.1:8000`.

## API

Основные endpoint'ы:

- `POST /api/audits` — создать аудит;
- `GET /api/audits/{job_id}` — статус и прогресс;
- `GET /api/audits/{job_id}/results` — результаты;
- `GET /api/audits/{job_id}/report.xlsx` — Excel-отчёт.

## Безопасность и ограничения

Backend ограничивает сетевые запросы и предназначен для проверки публично доступных HTTP/HTTPS-ресурсов. В MVP один аудит ограничен 500 страницами.

## Навигация по готовому аудиту

После проверки `job` сохраняется в URL. Общий аудит, Open Graph и Meta могут открывать один и тот же набор результатов без нового обхода сайта. По мере подключения следующих модулей они будут добавляться в эту же схему.

## Статус проекта

Работают два полноценных модуля: **Open Graph** и **Meta**. Следующие по плану — Canonical, Schema, Images и Sitemap.
