# HeadInspect --- handoff на 19.08.2026

## 1. Что это за проект

**HeadInspect** --- русскоязычный сервис массового технического аудита
сайта.

Основная идея: пользователь вводит адрес сайта один раз, HeadInspect
находит `robots.txt` и sitemap, получает список страниц (с ограничением
до 500 URL), проверяет их и показывает сводный и подробный отчёт.

Домены и ресурсы: - Основной сайт: `https://headinspect.ru` - API:
`https://api.headinspect.ru` - GitHub:
`https://github.com/dmitrystarosta/HeadInspect` - Telegram:
`t.me/headinspect` - Также зарегистрирован `headinspect.com`.

Цель проекта --- сделать полезный русскоязычный SEO/технический
инструмент с перспективой попадания в топ-10 поиска.

План модулей: 1. Open Graph --- первый рабочий модуль. 2. Meta (`title`,
`description`). 3. Canonical. 4. Schema. 5. Images. 6. Sitemap. 7. В
дальнейшем --- расширение общего технического аудита.

## 5. API

Рабочие endpoints:

### Health

`GET /health`

### Создание фонового аудита

`POST /api/audits`

Пример тела:

``` json
{"url":"https://example.ru"}
```

API возвращает `job_id`, URL статуса и URL результатов.

### Статус

`GET /api/audits/{job_id}`

Возвращает в том числе: - status - discovered_urls - checked_urls -
max_urls - limited - progress_percent - errors_found - warnings_found -
timestamps - error

### Результаты

`GET /api/audits/{job_id}/results`

Возвращает результаты по страницам.

Аудит работает в фоне, поэтому frontend не держит один длинный
HTTP-запрос: создаёт job, опрашивает status и после завершения получает
results.

## 12. Rate limit

19.08.2026 добавлен rate limit для запуска тяжёлых аудитов.

Внутри блока `http {}` файла:

`/etc/nginx/nginx.conf`

добавлено:

``` nginx
limit_req_zone $binary_remote_addr zone=headinspect_audit:10m rate=5r/m;
```

В HTTPS virtual host для API создан отдельный exact location:

``` nginx
location = /api/audits {
    limit_req zone=headinspect_audit burst=2 nodelay;
    limit_req_status 429;

    proxy_pass http://127.0.0.1:8000;

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_connect_timeout 10s;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}
```

Обычный `location /` сохранён для status/results/health.

Rate limit протестирован восемью быстрыми POST:

``` text
202
202
202
429
429
429
429
429
```

То есть ограничение реально работает.

**Важно:** эти production-конфиги Nginx существуют на VPS и пока не
являются полноценными файлами deployment-конфигурации в Git. В
дальнейшем стоит добавить в репозиторий пример production-конфигурации и
инструкцию восстановления VPS.

## 16. Последняя доработка 19.08.2026

После первого production-теста обнаружено два UX/архитектурных момента.

### 16.1 Главная страница должна быть первой

Backend вернул `/open-graph/` раньше `/`.

Это технически допустимо, но для пользователя нелогично.

В frontend добавлена сортировка:

1.  `/` всегда первая;
2.  затем страницы с errors;
3.  затем warnings;
4.  затем OK;
5.  внутри групп --- по пути.

### 16.2 Не сканировать сайт второй раз

Изначально:

главная → аудит → кнопка «Открыть подробный Open Graph-аудит» →
`/open-graph/` → **новый повторный аудит**.

Для сайта на 500 страниц это лишняя нагрузка.

Исправлено:

главная передаёт существующий `job_id` в `/open-graph/`, а подробная
страница получает уже готовый результат через API.

Таким образом:

**один запуск = одно сканирование сайта.**

Последний commit этой доработки:

`017a439 Reuse audit results and sort homepage first`

## 19. Что НЕ делать без необходимости

1.  Не открывать FastAPI `:8000` напрямую наружу.
2.  Не удалять SSRF-защиту private/local IP.
3.  Не убирать лимит 500 URL.
4.  Не снимать rate limit без замены другой защитой.
5.  Не менять Nginx без `sudo nginx -t`.
6.  Не запускать повторный аудит только ради перехода между
    представлениями одного результата.
7.  Не переделывать существующий визуальный стиль без причины ---
    текущий интерфейс уже устраивает и выглядит как рабочий сервис.

## 21. Концепция интерфейса, которую важно сохранить

HeadInspect задуман не как набор тяжёлых карточек на каждую страницу, а
как быстрый технический инструмент.

Основные принципы: - ввод домена один раз; - до 500 страниц; -
компактный список результатов; - статус **в начале строки**; - зелёный /
жёлтый / красный; - подробности раскрываются по клику; - отдельные
специализированные страницы инструментов; - главная постепенно
превращается в общий аудит; - русскоязычная аудитория; - простой
интерфейс в духе Google; - сервис должен быть понятен и обычному
владельцу сайта, и SEO/веб-разработчику.
