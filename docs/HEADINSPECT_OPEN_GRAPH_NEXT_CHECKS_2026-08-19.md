# HeadInspect --- идеи для расширения Open Graph-аудита

Дата: 2026-08-19

## Контекст

После сравнения текущего Open Graph-аудита HeadInspect с opengraph.xyz
выявлены дополнительные проверки, которые стоит добавить в следующих
версиях.

Текущий приоритет: не смешивать обязательные ошибки Open Graph с
полезными рекомендациями. Дополнительные теги должны отображаться как
предупреждения, если их отсутствие не делает базовый Open Graph
невалидным.

## 1. `og:site_name`

Добавить извлечение и проверку:

``` html
<meta property="og:site_name" content="HeadInspect">
```

`og:site_name` --- имя сайта/бренда. Это дополнительное Open
Graph-свойство, а не один из базовых обязательных тегов.

### Логика HeadInspect

-   тег присутствует и заполнен → OK;
-   тег отсутствует → предупреждение;
-   тег присутствует, но пустой → предупреждение;
-   не считать отсутствие `og:site_name` критической ошибкой.

### Что потребуется

Доработка backend:

-   извлекать `og:site_name`;
-   добавить поле в модель результата;
-   передавать значение через API;
-   добавить соответствующую проверку/предупреждение.

Доработка frontend:

-   показывать `og:site_name` в раскрывающейся диагностике страницы;
-   отображать отсутствие как жёлтое предупреждение.

Также добавить `og:site_name` на сам headinspect.ru:

``` html
<meta property="og:site_name" content="HeadInspect">
```

## 2. Проверка длины `og:title`

Добавить рекомендацию по длине `og:title`.

Важно: это должна быть именно рекомендация, а не жёсткая ошибка.

В интерфейсе желательно показывать:

-   фактическое количество символов;
-   нормальная длина → зелёный статус;
-   слишком короткий/длинный → жёлтое предупреждение.

Точные пороги перед реализацией стоит определить отдельно и
зафиксировать в правилах анализатора.

## 3. Проверка длины `og:description`

Аналогично `og:title`:

-   считать символы;
-   показывать фактическую длину;
-   нормальную длину отмечать зелёным;
-   слишком короткое/длинное описание --- жёлтым предупреждением;
-   не считать отклонение критической ошибкой.

## 4. `og:image:alt`

Добавить проверку альтернативного описания Open Graph-изображения:

``` html
<meta property="og:image:alt" content="Описание изображения">
```

Предлагаемая логика:

-   есть `og:image` и `og:image:alt` → OK;
-   есть `og:image`, но нет `og:image:alt` → предупреждение;
-   если самого `og:image` нет, отдельное предупреждение об
    `og:image:alt` не требуется, чтобы не дублировать одну проблему
    несколькими сообщениями.

## 5. Twitter/X Card

В перспективе добавить проверки:

``` html
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:image" content="https://example.com/image.jpg">
```

Возможные проверки:

-   `twitter:card`;
-   `twitter:image`;
-   при необходимости позже --- `twitter:title`;
-   `twitter:description`;
-   `twitter:image:alt`.

### Важный принцип интерфейса

Twitter/X Card желательно визуально отделять от собственно Open Graph.

Например, внутри диагностики страницы использовать группы:

-   Open Graph;
-   X / Twitter Card;
-   изображение.

Отсутствие Twitter/X-тегов не должно превращать корректный Open Graph в
красную ошибку.

## Приоритет реализации

1.  `og:site_name`.
2.  `og:image:alt`.
3.  Длина `og:title`.
4.  Длина `og:description`.
5.  Twitter/X Card как отдельная группа рекомендаций.

## Общий принцип HeadInspect

Нужно сохранять различие между:

**Ошибка** --- отсутствует или некорректен важный элемент, из-за
которого Open Graph-карточка может не работать должным образом.

**Предупреждение** --- карточка в целом может работать, но разметку
желательно улучшить.

**OK** --- проверка пройдена.

Так отчёт HeadInspect будет полезен не только как валидатор тегов, но и
как практический список рекомендаций без искусственного завышения
количества ошибок.
