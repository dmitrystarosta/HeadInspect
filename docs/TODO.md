## P1 — следующий этап

### Meta и качество текста

- [ ] Обнаруживать явно повреждённый текст в метаданных.
  - Первый надёжный признак: символ замены Unicode `�` (`U+FFFD`).
  - Проверять как минимум:
    - `<title>`;
    - `meta description`;
    - `meta keywords`;
    - текстовые Open Graph-поля.
  - Показывать предупреждение вроде:
    **«Возможна ошибка кодировки: в содержимом обнаружены некорректные символы.»**
  - Не считать это критической ошибкой страницы.
  - Реальный тест-кейс: `zipkran.ru/video/`, где повреждён `meta keywords`,
    тогда как остальная кириллица страницы корректна.

- [ ] Позже изучить возможность обнаружения типичных «кракозябр»
  (`РџСЂРё...` и подобных).
  - Перед реализацией оценить риск ложных срабатываний.

### Open Graph

- [ ] Добавить проверку `og:site_name`.
  - Определить, считать отсутствие предупреждением или рекомендацией.
  - Не делать поле обязательным без отдельного обоснования.

### Защита API

- [ ] Рассмотреть суточный лимит запусков с одного IP.
  - Вводить только при наличии реальной необходимости по статистике.

- [ ] Улучшить диагностическое логирование аудитов.
  - Время выполнения.
  - Количество реально начатых/завершённых URL.
  - Причина partial audit.
  - Массовые timeout / 403 / network errors.
  - Не логировать лишние пользовательские данные.
